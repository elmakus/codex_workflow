### Code Mode ownership evidence

The Codex rollout for the thread contains exactly one top-level custom Code Mode tool call named `exec`.

Inside that single JavaScript cell, Code Mode:

1. called `tools.exec_command` with the controlled 125-second command and a 30-second initial command yield;
2. retained the returned native terminal session inside the same cell;
3. looped on `tools.write_stdin` inside the same cell while a session id remained;
4. observed terminal exit code `0` and exact output `HEALTHY_WAIT_OK`;
5. returned control to Main only after terminal completion.

There is no recurring top-level Main-driven terminal/session liveness loop in the rollout for this healthy interval.

### Codex-LB request-count evidence

For the same conversation id, Codex-LB recorded exactly two successful Main requests:

| requested_at | model | effort | status |
|---|---|---|---|
| 2026-09-20 17:56:20.109695 | gpt-5.6-sol | medium | success |

The interval between those requests is about 128.21 seconds. There are no intervening Main requests while the controlled command is healthy and merely still running.

Interpretation:

- first request = dispatch / creation of the one-cell wait;
- second request = continuation after terminal completion;

This directly demonstrates the native host mechanism required by the M05 feasibility gate: the outer Code Mode cell can own a multi-minute terminal wait across the ordinary initial shell-yield boundary without periodic Main inference.
