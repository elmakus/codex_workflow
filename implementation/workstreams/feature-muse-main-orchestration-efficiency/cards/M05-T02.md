- Internal terminal-session waiting is explicitly runtime-owned inside that cell; Main is re-entered only for terminal result/failure/timeout/cancellation, explicit user interaction or another genuinely material event.
- The active contract explicitly rejects repeated Main-driven `write_stdin`/status polling, liveness timers/heartbeats and unmanaged background-process polling.
- Existing Muse timeout/cancellation, session-busy/fail-closed recovery, logical-session binding, Executor/Tester independence and private-artifact invariants remain GREEN in applicable regressions.
- Focused profile/documentation tests cover the native event-driven wait contract.
- A real Muse worker invocation remains healthy for at least several minutes and completes normally through the existing logical Muse runtime contract.
- For that exact live run, Codex-LB has no periodic Main requests between dispatch and terminal/material completion, excluding explicit user input or a genuinely material event.
- Matching Codex rollout contains one outer Code Mode `exec` ownership interval and no recurring top-level Main-driven liveness wait loop.
- `plus` source/profile behavior remains unchanged by the implementation and its existing regressions remain GREEN.
- Durable evidence records exact reviewed implementation subject, focused regression results and sanitized live-run identifiers/readback.
