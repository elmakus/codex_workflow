### Must preserve

- Codex Main remains the orchestrator; Muse remains responsible for Muse-native skill loading, MCP/tool execution and availability reporting.
- The v1 contract has exactly four semantic categories: required skills, relevant skills, required capabilities and suggested capabilities.
- Hints are complete per-invocation replacement data. Resume must supersede prior-turn hints, including when the current set is empty.
- Required entries are fail-visible when unavailable; relevant/suggested entries are advisory and non-blocking.
- Identifiers are bounded, syntactically safe opaque IDs; no global taxonomy, alias resolver or mandatory registry is introduced.
- Required-over-advisory precedence applies only within the corresponding skill or capability namespace, while preserving stable caller order.
- Hints contain identifiers only. They do not carry credentials, capability implementations, installation instructions or mutation authority.
- Missing required capability does not authorize installation/configuration/authentication/update/removal.
- Executor and Tester remain distinct logical worker/session identities even when they receive the same domain capability hints.
- Existing capability-free Muse calls and non-`muse-max` compute-profile behavior remain unaffected.

## Scope

### Included

- Add a frozen structured `MuseCapabilityHints` value and attach it to `MuseWorkerInvocation`.
- Define one centralized normalization/validation path for all four categories.
- Bound and validate safe opaque identifiers; stable-deduplicate entries; remove advisory duplicates shadowed by required entries in the same namespace.
- Add equivalent repeatable CLI inputs for all four categories and route them through the same normalizer as Python callers.
- Forward normalized hints through direct and concurrent Muse execution.
- Render a deterministic `CURRENT MUSE CAPABILITY HINTS` block on every invocation, including an explicit empty set.
- State in that block that it is authoritative for the current invocation and supersedes all prior-turn hints, including on resume.
- State required-failure versus advisory semantics without adding any auto-install/repair behavior.
- Update `codex_workflow/delegation.md` with Main-side guidance for populating hints and maintaining the separate capability-administration plane.
- Add focused and regression tests for direct/CLI/concurrent/initial/resume/empty/duplicate/conflict semantics and Executor/Tester isolation.

- Reading secrets or capability stores.
- Capability discovery, global registry/catalog, alias resolution or provider selection.

## Acceptance

- Python callers can pass all four hint categories through `MuseWorkerInvocation` / direct execution and receive deterministic normalized semantics.
- The normal CLI exposes equivalent repeatable inputs and produces the same normalized representation.
- Invalid identifiers fail closed before Muse launch.
- Duplicate entries retain first caller order; an entry present in required and advisory form in the same namespace appears only as required.
- Every generated worker prompt contains the current four-category block; an empty invocation explicitly renders no current hints.
- A resumed invocation's block states replacement semantics and contains only the current invocation's normalized hints.
- Required skill/capability unavailability is instructed to be reported fail-visibly; relevant/suggested unavailability is explicitly non-blocking.
- The runtime does not install/configure/authenticate/update/remove capabilities or expose secret material because of hints.
- Concurrent invocation forwarding preserves each lane's independent current hints.
- Executor/Tester logical-session isolation remains unchanged.
- Existing capability-free adapter behavior and non-`muse-max` profile behavior remain GREEN.
