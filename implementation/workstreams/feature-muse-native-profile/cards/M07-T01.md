### Must preserve

- Exactly `plus`, external `muse-max`, and native `muse-native` remain supported.
- All six `muse-native` workers use native Codex configuration with `muse-spark-1.3-contributor`, `max`, and the configured CLIProxyAPI provider route.
- Provider/model/effort selection fails visibly; no silent fallback.
- `plus` and external `muse-max` behavior remain unchanged.
- Internal Codex agents are enabled for `plus` and `muse-native`; external `muse-max` keeps its current disabling behavior.
- Preserve unrelated user Codex/provider settings and profile-switch rollback/idempotency.
- Authentication secrets stay outside repository, task capsules, generated docs, and normal evidence.

### Must not

- Do not make repository code own login/token storage or credential migration.
- Do not reuse the external Muse adapter/session/JSONL/wait/capability-hint stack for `muse-native` merely for symmetry.
- Do not change VERSION, release/tag, or deployment state.
- Do not implement M08 lifecycle parity beyond minimum M07 profile/config hooks.

## Dependencies

- none

## Outcome

The runtime can select and render `muse-native` as the third profile with exact native worker model/effort/provider intent and minimal safe provider-setting ownership, with no regression to the existing profiles.

## Scope

### Included

- Extend compute-profile validation/summary/allocation to `muse-native`.
- Add minimum workflow-owned provider selector/rendering for native worker TOMLs/config while preserving unrelated provider configuration.
- Render all six native workers and enable internal agents for `plus` + `muse-native`.
- Add the `muse-native` communication-policy rendering hook required for coherent profile application.
- Add focused tests for exact worker/provider identity, existing-profile preservation, config ownership, switching/rollback, and secret-free output.
- Add an isolated non-mutating provider/config smoke surface that distinguishes supported routing/config shape from an unconfigured external auth environment.

### Excluded

- Creating/changing Muse/Meta login or credentials.
- Final live auth-backed provider acceptance; this is the M07 JIT successor after implementation shape is known.
- M08 wait/resume/freshness/Tester/Investigator/MCP/skill/cancel runtime parity.
- Any retirement/change of external `muse-max`.
- VERSION/tag/release/deployment changes.

## Acceptance

- Exactly the three approved profiles are selectable.
- `muse-native` summary and all six rendered worker TOMLs expose exact Contributor/Max/native/provider intent.
- Applying `muse-native` enables internal agents; switching all three profiles preserves expected enablement and unrelated settings.
- `plus` and `muse-max` have no unintended rendering/config regression.
- Provider ownership is minimal and fail-closed; profile operations do not write or expose auth secrets.
- Isolated provider/config smoke reports an exact unsupported/missing-environment condition instead of silently falling back.
- Transaction failure preserves existing rollback guarantees.
