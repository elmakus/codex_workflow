## JIT predecessor facts

M07-T01 established the exact provider/config shape:
- `muse-native` uses native Codex workers with `muse-spark-1.3-contributor`, `max`, provider `cliproxyapi`;
- provider configuration is user-owned and must use the Responses wire API;
- workflow-owned worker provider selectors are marked and reversible;
- credentials remain external to repository/evidence.

Current-source inspection after M07-T01 also proves one M07 update-preservation defect: `runtime/runtime_ops.py::plan_platform_and_workers` still enables internal agents only when `profile == "plus"`. An update while `muse-native` is selected would therefore render the selected native workers but disable the native agent surface.

## Included scope

1. Reconcile update/runtime materialization so a selected `muse-native` profile:
   - remains selected across update;
   - keeps internal Codex agents enabled;
   - preserves exact worker model/reasoning/provider rendering;
   - validates the required user-owned provider route before applying update mutations;
   - preserves unrelated Codex/provider settings and authentication ownership.
2. Add focused regression coverage for:
   - `muse-native` selected-profile preservation across update;
   - exact worker/provider/agent-enable state after update;
   - fail-closed update behavior for missing/incompatible required provider configuration;
   - preservation of unrelated provider/config data;
   - existing `plus` and external `muse-max` update behavior.
3. Run one isolated live provider-level smoke in the installed environment using the already-configured user-owned CLIProxyAPI route:
   - pin provider `cliproxyapi`, model `muse-spark-1.3-contributor`, and reasoning `max`;
   - prove a real Codex request succeeds through that exact route, or capture the precise external-environment blocker/error class;
   - do not create, copy, print, persist, rotate or otherwise manage OAuth/token material.
4. Persist concise non-secret evidence usable by later M08/M09 acceptance.

## Excluded scope

- Full native worker lifecycle parity, all-six-role live launch, continuation/freshness/Tester/Investigator/cancel/recovery acceptance — M08/M09.
- MCP/skill live acceptance — M08/M09.
- External `muse-max` adapter/session/JSONL/wait/capability redesign.
- Login/device-flow credential setup or CLIProxyAPI credential-store mutation.
- VERSION, release, tag, deployment or production publication.
- Retirement of `muse-max`.

## Must preserve

- Exactly three supported profiles: `plus`, `muse-max`, `muse-native`.
- `plus` behavior unchanged.
- External `muse-max` behavior unchanged and native agents disabled while that profile is active.
- Main remains user-selected.
- No silent provider/model/effort fallback.
- No secret material in repository state, normal logs/evidence or Task Board.
- Update/profile operations remain transactional and preserve unrelated user state.

## Acceptance

- A regression that fails on the M07-T01 baseline demonstrates the native-update agent-enable defect and becomes GREEN after correction.
- Updating with selected `muse-native` preserves `settings.toml = muse-native`, all six worker allocations, `model_provider = "cliproxyapi"`, quiet-policy rendering and `[agents].enabled = true`.
- Missing or incompatible required provider configuration fails before update application rather than leaving an apparently active native profile with an unusable/silent alternate route.
- Unrelated provider/config fields remain byte/semantic-equivalent as appropriate; workflow does not write auth secrets.
- Existing `plus` and `muse-max` update regressions stay GREEN.
- The live provider smoke either:
  - succeeds with the exact pinned provider/model/effort route; or
  - records a precise environment/auth/provider blocker without fallback and without credential mutation.
- Required repository tests/checks are GREEN: focused profile tests, workflow runtime regressions, Muse adapter regressions, compile, package validate/build/archive verification.

## External/readback rule

Live smoke uses the existing installed provider/account state only. Read and report only non-secret route metadata and terminal success/error classification. If the existing external credential/config state is insufficient, persist the precise blocker and stop that live sub-obligation rather than attempting login or credential repair.
