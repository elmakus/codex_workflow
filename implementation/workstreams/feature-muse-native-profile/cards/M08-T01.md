## JIT predecessor facts

M07 proves the selected native allocation and provider shape: all six `muse-native` roles are internal Codex workers at `muse-spark-1.3-contributor` / `max` / `cliproxyapi`, while external `muse-max` retains its separate Muse adapter/session stack.

Current-source inspection shows the orchestration documents still encode a two-profile split in several operational surfaces:
- Heavy explicitly routes only `plus` through the internal Codex lifecycle and names material-event handling as plus-only;
- Delegation describes fresh internal workers and material-event push as plus-only while external Muse sections are `muse-max` specific;
- project `AGENTS.md` and installed `user_AGENTS.md` do not yet express the native-profile dispatch/material-event rules;
- the operational profile guide exposes only `plus` and `muse-max`.

The underlying generic internal-worker contracts already contain no-poll `wait_agent`, direct-to-Main results, exact-three Investigator lanes, independent Tester repair/recheck, and fresh-worker semantics. M08 should bind `muse-native` to those native contracts rather than create a second scheduler/session subsystem.

## Included scope

1. Reconcile Heavy/delegation/project and installed dispatch guidance so `muse-native`:
   - uses the normal native Codex worker lifecycle for all six roles;
   - uses native long wait/continuation semantics without Main-driven status/list/progress polling;
   - resumes the same owning native worker/thread for ordinary follow-up/repair when safe;
   - uses a genuinely fresh internal worker with no inherited turns for controlling freshness/independence;
   - preserves distinct Executor/Tester identities and the ordinary RED → owning Executor repair → same Tester full recheck flow;
   - preserves exactly three independent Investigator lanes, direct-to-Main reporting and safe non-overlapping concurrency.
2. Extend the bounded native Material Event Push contract to `muse-native` with the same BLOCKER / COURSE_CHANGE / CRITICAL_PARTIAL and no-routine-progress/no-sibling rules as `plus`; keep external `muse-max` outside this internal channel.
3. Make native capability guidance explicit:
   - `muse-native` uses the native Codex MCP/tool/skill plane;
   - do not route it through `MuseCapabilityHints`;
   - a required native capability that is unavailable must fail visibly rather than trigger silent transport/provider substitution.
4. Reconcile the operational profile guide and installed user dispatch invariant for the third profile.
5. Add focused static/render/profile regressions proving the above contracts and proving external `muse-max` transport sections remain scoped only to `muse-max`.

## Excluded scope

- OAuth/provider/account setup or mutation.
- Claiming live MCP/skill, wait, continuation, freshness, cancellation/recovery or all-six-role acceptance without live evidence.
- A new native scheduler, session registry, JSONL/raw-run layer, subprocess adapter, background polling shim or `MuseCapabilityHints` bridge.
- Public README/workflow-breakdown/release-documentation reconciliation and A/B matrix — M09.
- VERSION, tag, release, deployment or retirement of external `muse-max`.

## Must preserve

- M07 provider/model/effort allocation and fail-closed provider behavior.
- Main remains the user-selected Codex model and central orchestration authority.
- Existing `plus` semantics remain unchanged except wording may generalize an already-native contract to `plus | muse-native`.
- External `muse-max` adapter/session/capability-hint/one-cell wait behavior remains unchanged and isolated to that profile.
- No direct sibling messaging.
- No Main-driven liveness polling.
- No weakening of Tester independence, exact-three Investigator lanes, freshness or same-owner repair semantics.
- No secret/account material in repository or normal evidence.

## Acceptance

- Operational dispatch clearly distinguishes:
  - `plus`: native Codex workers with existing allocation;
  - `muse-native`: native Codex workers with the M07 Muse allocation/provider;
  - `muse-max`: external `runtime/muse_worker.py` lifecycle only.
- Heavy/delegation state that healthy native worker waits use normal long `wait_agent` continuation semantics and that a timeout/no-new-state result alone does not justify polling/replacement/Main takeover.
- Same-worker continuation, fresh-context creation, independent Tester repair/recheck and exact-three Investigator contracts explicitly cover `muse-native`.
- Material-event push explicitly covers `plus` and `muse-native` and excludes external `muse-max`.
- Native MCP/skill capability guidance is explicit and fail-visible without introducing transport-specific compatibility machinery.
- `user_AGENTS.md` and `operate/profile.md` expose the third profile and prevent `muse-native` from routing through `muse_worker.py`.
- Focused regression assertions fail on the pre-Card text contract and pass after reconciliation.
- Existing runtime/profile/Muse adapter regression suites, compile and package validation/build checks remain GREEN.
