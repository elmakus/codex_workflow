### Must preserve

- Main remains the user-selected Codex model.
- The native worker allocation is exactly `muse-spark-1.3-contributor` / `max` / `cliproxyapi`, fail-closed with no provider/model/effort or harness fallback.
- The worker uses the native Codex lifecycle; do not invoke `runtime/muse_worker.py`, Muse logical sessions, JSONL/raw-run transport, one-cell Muse waiting or `MuseCapabilityHints`.
- Ordinary continuation resumes the same owning native worker/thread; failed resume must be visible rather than relabeling a replacement.
- Capability proof uses the native worker capability plane and must not copy secrets or capability bodies into repository evidence.
- Existing `plus` and external `muse-max` behavior remain unchanged.
- User-owned provider/account/OAuth/client-auth state remains outside repository ownership.

### Must not / rationale that must travel

Do not broaden this first live gate into the entire M08 acceptance matrix. Fresh-context isolation, the full Executor/Tester RED-repair-recheck flow, exact-three Investigator execution, multi-minute no-poll evidence and cancel/recovery remain downstream JIT work after this Card establishes the first real native worker/provider/capability path.

## Dependencies

- `M08-T01` done with independent review GREEN.
- User-owned workstation prerequisite: a usable Codex `[model_providers.cliproxyapi]` Responses route plus CLIProxyAPI Muse/Meta OAuth/client-auth state must already exist. This Card must not create or repair credentials.

## Outcome

Prove on the exact installed workstation that one `muse-native` worker can execute through the native Codex lifecycle with the required Muse provider/model/effort, use one required native MCP and one required installed skill, and resume the same native worker/thread once without falling back to the external Muse transport.

## Scope

### Included

1. Re-read the exact installed Codex/workflow/provider state before mutation; abort fail-closed if the required provider route is still absent/incompatible.
2. Record the current compute profile and use the existing transactional profile operation to select `muse-native` only for the bounded live probe.
3. Verify post-switch readback:
   - selected profile is `muse-native`;
   - native agents are enabled;
   - all six rendered worker definitions retain the M07 Muse model/reasoning/provider allocation;
   - unrelated user configuration is preserved.
4. Launch one native Tester worker for a harmless read-only verification task.
5. Require that worker to exercise:
   - enabled native MCP surface `node_repl` with a deterministic no-side-effect check;
   - installed read-only `review-agent` skill on a bounded disposable/read-only review target.
6. Resume the same native worker/thread once for an ordinary follow-up and capture exact continuity identity.
7. Capture non-secret evidence sufficient to distinguish the exact provider/model/effort/native-worker route and to show that no external Muse worker/session transport handled the probe.
8. Restore the pre-probe compute profile `muse-max` in a compensating cleanup path and verify the selected profile/native-agent state is restored.

### Excluded

- Creating, copying, printing, persisting, rotating or repairing any API key, OAuth token, CLIProxyAPI client credential or account state.
- CLIProxyAPI upgrade unless later evidence proves the installed version incompatible after the prerequisite is configured.
- Full all-six-role live acceptance.
- Fresh-context proof.
- Full Executor/Tester RED → repair → same Tester recheck acceptance.
- Exact-three live Investigator lanes.
- Multi-minute no-poll/Main-request telemetry acceptance.
- Timeout/cancel/recovery/orphan acceptance.
- M09 A/B comparison, public docs/release work or retirement of external `muse-max`.

## Acceptance

- Preflight proves the exact user-owned `cliproxyapi` Responses route exists before any profile mutation; otherwise the Card remains blocked with no fallback.
- The bounded profile transaction selects `muse-native` and readback proves native-agent enablement plus all six exact worker allocations.
- One real native Tester worker completes through `cliproxyapi / muse-spark-1.3-contributor / max`; evidence contains no silent alternate provider/model/effort/harness.
- The same worker successfully uses the required `node_repl` MCP surface and the installed `review-agent` skill, or capability absence fails visibly with exact non-secret evidence and no substitution.
- One ordinary follow-up resumes the same native worker/thread and the identity is demonstrably unchanged.
- Evidence proves the probe did not route through `runtime/muse_worker.py` or create/use an external Muse logical session for the native role.
- The original `muse-max` profile is restored after success or failure and readback confirms the restored installed state.
- No credential or secret material enters repository state/evidence.
- Existing repository M08-T01 focused/runtime/Muse-adapter regressions remain GREEN if repository/source state is touched; no repository source change is required merely to run the live probe.
