# M01-T01 — Same-version project-only update path

- Milestone: `M01`

## Authority slice

- Master Plan: `planning/MASTER_PLAN.md#M01--project-only-update-and-legacy-migration-hardening`
- Requirements: `REQ-001`, `REQ-002`, `REQ-003`, `REQ-004`, `REQ-021`
- Accepted decision: `decisions/DEC-004-selective-upstream-adoption.md`
- Research: `research/upstream-1.1.18-audit.md`
- OpenSpec: JIT before implementation.

### Must preserve

Historical `.source_backup/<version>` resolution, multi-project catch-up, explicit downgrade protection, owner-release source policy, installed shared runtime/worker state on the equal-version project-only path, unrelated user/project state, and existing transactional safety.

### Must not / rationale that must travel

Do not replace/download shared runtime when the installed verified source already matches the selected release. Do not broaden into legacy-route validation, worker/profile changes, VERSION/release metadata, publication, or wholesale upstream merge/cherry-pick.

## Dependencies

- none

## Outcome

An installed-current workflow can bring an older project to that same version using installed verified source only, with project-scoped mutation/backup and a true current-project no-op.

## Scope

### Included
- Equal-version CLI selection/delegation behavior.
- Project-only lifecycle planning and scoped backup behavior.
- Downgrade/historical-source preservation on that path.
- Focused regression coverage.

### Excluded
- Legacy local-instruction stale-route validation (`M01-T02`).
- M02+ topology/profile/documentation changes.
- `codex_workflow/operate/VERSION`, synchronized release markers, tags/releases/deployment.

## Acceptance

- No release acquire/download is needed when selected version equals installed version and installed source is authoritative.
- Updating an older project at equal runtime version mutates only required project state/files; installed shared runtime/worker state is unchanged.
- Backup contains only existing target-project files actually changed.
- Already-current project is a no-op and creates no backup.
- Project-newer-than-incoming remains blocked without explicit downgrade approval.
- Historical-source mismatch/missing backup still fails closed; existing multi-project behavior remains GREEN.

## Required tests / checks

Extend focused runtime regressions for no-download selection, shared-runtime immutability, scoped backup, current-project no-op, downgrade, historical-source and multi-project catch-up; run affected runtime suite.

## External write/readback needs

Repository branch only; no live deployment or release publication.

## Independent review

`REQUIRED` — update/backup/downgrade behavior is a material data-integrity and migration safety boundary.
